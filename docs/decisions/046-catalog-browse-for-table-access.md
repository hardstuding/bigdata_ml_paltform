# 046. 表访问申请改成浏览目录勾选,不是手打完整表名

- 状态: 已采纳,已实现

## 背景

ADR-044 实现的表访问申请入口是一个纯文本输入框,要求申请人手打完整表名
(比如 `trino.iceberg.demo.orders`)。用户实测反馈:这对不熟悉具体表名的
人不友好,不像一个"好用的 OA 表权限申请系统"——真实场景里,申请人往往
知道自己要访问哪类数据,但不一定记得住 catalog/schema/table 的精确拼法,
应该能像浏览一个目录一样搜索、按安全等级筛选、勾选多张表一起提交,而不是
死记硬背表名。

## 决策

### 新增 `/table-access/catalog`:浏览 + 筛选 + 勾选提交

新路由列出 OpenMetadata 里已经登记过的表(建表注册工具回写的那些,
`list_catalog_tables()`),支持:
- 关键字搜索(表名模糊匹配)
- 按 schema 筛选(下拉框,选项从当前目录里出现过的 schema 名动态生成,
  不是写死的列表)
- 按安全等级筛选(L1/L2/L3)
- 每张表旁边直接显示安全等级徽章、负责人、列名预览——ADR-040 原文
  "对应的表也要有注明"这条要求
- 勾选多张表,一次提交,每张表各自走自己的审批链(不同表可能安全等级
  不同,审批人也不同,天然是独立的申请,不能合并成一条)

原来的手打表名入口(`/table-access/request`)保留,不强制所有人走目录
浏览这条路——已经确切知道表名的人(比如脚本/自动化场景)不需要多点几次
筛选器。首页把这个入口的说明文字改成"不知道确切表名?去浏览目录申请",
引导但不强制。

### 复用同一套提交逻辑,不写两遍

把原来 `submit_table_access` 里"查 OpenMetadata、算审批链、插入申请"这段
逻辑抽成 `create_table_access_request()`,单张提交(`/table-access/
request`)和批量提交(`/table-access/request-batch`,目录页勾选多张用)
都调用这同一个函数,不重复实现两遍容易走样的业务逻辑。

### 提交时仍然重新查一次 OpenMetadata,不信任目录页展示的数据

目录浏览页显示的安全等级/负责人是查询那一刻的快照,提交时
`create_table_access_request()` 还是会重新调 `lookup_table_governance()`
真实查一次——不是把浏览页面上看到的值直接塞进表单当真,防止表在浏览和
提交之间被改了标注(小概率,但这是权限相关的判断,宁可多查一次)。

### 明确不做的:行/列级细粒度选择

用户提到"有些表还有行列要求"。这次**没有**做成结构化的"勾选具体列/填行
过滤条件"的输入控件——现在完全没有任何执行引擎会去消费这种结构化数据
(Trino OPA 细粒度权限还没做,ADR-028"后续"里的独立工作),先做一个没人
会用的精细输入框没有意义。这次只在批量提交表单上加了一个共享的"申请
理由"文本框,申请人可以在这里写清楚"只需要哪几列/哪个时间范围",给审批人
看、留痕,但不是结构化数据,不会被自动解析/执行。等 Trino OPA 真正落地、
需要消费"这个人被批准访问哪些列"这类结构化数据时,再回来给这个输入框
升级。

## 验证

用重新授权过的 OpenMetadata bot(见会话记录,原来的 `admin1` bot 角色是
空的,403 Forbidden,换了一个有 Admin 角色的 bot 之后 `GET /api/v1/
tables` 返回 200)。目录浏览页在 `OPENMETADATA_TOKEN` 无效/未配置时会
显示"目录暂时看不到"的提示,不会整页报错——这条路径已经在旧 token 失效
期间被动验证过(不是刻意测的,是真的撞上了这个场景)。真实注册一张表、
确认它出现在目录列表里、勾选提交、走完一次审批链的验证见后续记录。
