# 013. 生产容量基线(参考数据,非决策)

- 状态: 记录(2026-08-09)

这条不是架构决策,是把用户提供的现有生产环境规模记下来,给以后 cloud-full/prod
的资源规划做依据,避免凭空估算。

## 现有(旧)Spark 集群

- **6 台服务器**,每台 **256GB 内存**,约 **50TB 存储**(总计约 1.5TB 内存 /
  300TB 存储)
- 现有 Spark 作业普遍偏重,很多任务起步就要 **24 核 × 10GB** 这个量级的资源
  才能跑起来,不是轻量任务

## 对新平台资源规划的含义

- [architecture.md](../architecture.md) 里给的"生产参考区间"(平台底座
  4-8GB、湖仓查询 16-32GB、数据工程 16-32GB、AI/ML 8-16GB)是按"中小团队、
  中等数据量"给的通用框架估计,对比这里的真实基线明显偏保守——仅 Spark
  这一层的历史基线就已经是 1.5TB 内存规模。
- 新平台不是要一次性达到旧集群的规模,而是先在小规模上把架构、GitOps 流程
  跑通(local-lite → cloud-full 的一个较小规模环境),旧集群的资源后续
  用于替换/迁移阶段。
- 单次 Spark 作业 24核×10GB 起步这个信息,说明 Spark Operator 的资源配置
  (`SparkApplication` 的 executor/driver 资源请求)不能照抄 local-lite 那种
  几百 MB 的量级,cloud-full 阶段要按这个真实基线重新设定。
