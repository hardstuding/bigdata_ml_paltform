# 006. AI Agent 身份 v1:从简,不单独造一套 Agent RBAC

- 状态: 已采纳(2026-08-08)

## 背景

平台设想未来 AI Agent 是和人类工程师平级的操作者。但过早设计一套专门的"Agent 身份/权限系统"存在过度设计的风险 —— 现阶段还没有真实的多 Agent 协作场景需要支撑。

## 决策

v1 阶段,AI Agent 的身份能力就是:

1. Keycloak 里的 service account(和人类用户走同一个身份系统,不是平行系统)。
2. Git 仓库的分支权限 / PR 流程(操作平台 = 提交 Git 变更,见 [ADR-005](005-argocd-gitops.md))。

不额外构建独立的 Agent RBAC 引擎、不做多 Agent 协同调度。

## 理由

- 当前的实际操作者是"用户 + 单个 Claude Code 会话",不是多 Agent 系统。为不存在的场景预先设计协调机制是浪费。
- Keycloak service account 已经是标准能力,足够表达"这是一个非交互式身份,应该被审计、应该有权限边界"这件事,不需要发明新概念。

## 后果

- 以后如果真的出现多 Agent 并行操作的场景,需要重新评审这个决策,可能要引入更细粒度的权限模型 —— 但那是"用真实需求驱动架构演进",不是提前预留。
- 现阶段的审计能力约等于"Git 提交历史 + ArgoCD 同步记录",没有专门针对 Agent 行为的额外审计层。
