# ADR-069:成本归属用 OpenCost,单价必须自己填

日期:2026-08-23
状态:配置完成,**未部署验证**

## 背景

[`docs/production-readiness-gaps.md`](../production-readiness-gaps.md) 第 4 条。
它和 [ADR-064](064-role-based-resource-quota.md) 是一体两面:

- Kueue 回答**"能用多少"**(事前配额)
- OpenCost 回答**"实际用了多少、值不值"**(事后账单)

**只有配额没有账单,配额就变成一场纯粹的办公室政治**——每个组都说自己
不够用,而没有任何数据支撑谁该多分。zhenghe 自己这台按量付费机器就是这个
问题的缩影:本次会话之前有一段空转烧掉约 ¥25,是他自己发现的,不是从
任何仪表盘上看出来的。

## 决策:OpenCost 2.5.29(chart)/ 1.121.1(应用)

OpenCost 是 CNCF 项目,也是 Kubecost 的开源内核。选它没什么悬念:唯一
的真替代品 Kubecost 免费版有节点数限制,又是一个授权陷阱。

按 namespace / label 出成本,和 Kueue 的队列标签对齐,这样"哪个组花了
多少"和"哪个组能用多少"是同一套维度,能直接对照。

## 最关键的一条:`customPricing` 必须开,单价必须自己填

OpenCost 默认那套单价是按公有云一般水平写的(CPU **$1.25** /核/小时)。
放在阿里云 ECS 或者自有机房上,算出来的数字**完全没有意义**。

**而且比"不算"更糟,因为它看起来是个数。** 一个带着两位小数、出现在
Grafana 面板上的成本数字,没有人会去质疑它的来源——这正是这个项目反复
栽跟头的那种"看起来成功了"。

三档的处理方式不一样,理由都写在 `environments/resource-profiles.yaml` 里:

| 环境 | 单价 | 依据 |
|---|---|---|
| local-lite | **0** | 本机没有真实成本。填假单价只会让本地数字和云上对不上,反而误导 |
| cloud-full | CPU ¥0.168/核/时,内存 ¥0.021/GiB/时 | 从 ecs.g9i.4xlarge 实际 ¥4.04/小时反推,按"CPU 占 2/3、内存占 1/3"拆分 |
| prod | 同 cloud-full | zhenghe 2026-08-23:"按一般云服务的计算就好了"。用**等价云价格**当尺子,不是自有服务器的真实 TCO |

cloud-full 那个 2/3 : 1/3 的拆分比例是行业惯例,**不是阿里云的官方口径**。
它影响的是"CPU 密集型作业和内存密集型作业谁背更多成本"。在没有官方拆分
的前提下,有一个说得清来源的比例,远好过用 chart 默认的美元单价。

GPU 单价显式填 0 而不是留默认值:留一个假的 GPU 单价,等哪天真加了 GPU
节点,账会**静默**偏掉。

### prod 用云价当尺子,要知道它替代掉了什么

自有服务器的真实成本是"硬件摊销 + 机房托管 + 电费 + 运维人力",和云单价
不是一回事(通常自有更便宜,尤其在机器跑满时)。用云价得到的**绝对金额
偏高,但相对比例是对的**——而 OpenCost 在这个平台上要回答的主要问题是
"哪个组花得多、哪个作业最贵",这个问题只依赖相对比例。

**什么时候必须换成真实 TCO**:要拿这个数字对外报价、做预算申请、或者
做"上云还是自建"的对比时。那时候绝对值才重要。这条写在这里,是为了几个月
后有人拿这个数去做那类决策时,能先看到这行字。

## 两个部署细节

- **UI 不开。** 成本数据的正确去处是已有的 Grafana。再开一个自带 UI 就是
  第二个要配 SSO、要维护 Ingress 的入口。
- **Prometheus 的 Service 名是这个组件第一次部署最可能出错的地方**:
  `kube-prometheus-stack-prometheus.monitoring:9090`(名字规则是
  `<Helm release 名>-prometheus`,而 ArgoCD 默认用 Application 名做 release
  名)。错了的表现是 **opencost 起得来、不 CrashLoop,只是所有成本都是 0**
  ——所以首次部署要主动看它的日志,不能只看 Pod Running。

## 还没做的

1. 没部署验证。
2. **没有 Grafana 面板。** 指标被抓上去了不等于有人看得到。面板要能回答
   "这个月各组花了多少""哪个作业最贵",而不是一堆原始指标。
3. prod 单价还是 0,要 zhenghe 提供实际数字才有意义。
