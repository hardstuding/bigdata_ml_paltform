# ADR-067:门户从"链接目录"改成"工作台"

日期:2026-08-23
状态:代码 + 测试完成,**镜像和集群验证未做**(改完源码要等 CI 重建镜像、
更新 deployment 里的 digest,再上集群看)

## 背景

zhenghe 2026-08-23 的原话:"我想你当前设计的门户网站、还有一些自己做的
功能,是不是还有优化空间?我之前看了,ui 设计和功能感觉都不是很好。"

拆开看是三个不同的问题,不是一个"审美"问题:

### 1. 它只是个链接目录(功能问题,也是主要问题)

改造前 230 行,内容是 13 个工具的卡片 + 一个在线状态点。**它唯一超出
浏览器书签栏的能力是现场探活。**

一个人打开门户真正想知道的是:我昨天那个任务跑成功了吗?我们组配额还剩
多少?我有哪些表的权限?我的审批到哪一步了?——**这些数据平台里全都有**
(Argo、Kueue、IAM 表、审批后端),只是没有一个地方按"人"聚合过。现在的
做法是让人自己去五个系统里各翻一遍。

### 2. 13 个探测是串行的(性能问题,大概率就是"感觉不好"里最实在的一部分)

每个探测超时 1.5 秒,串行执行。只要有几个组件是 park 状态,页面就要转
好几秒;全部 park 的极端情况要等 **19.5 秒**。而 park/unpark 在这台机器上
是常态。

### 3. HTML/CSS 内联在 Python 字符串里(可维护性)

改一个颜色要动 `src/app.py`。

## 决策

### 页面结构改成"先我的,再资源,最后入口"

```
我的作业     ← 我提交的任务跑成什么样了
计算配额     ← 我们组能用多少、现在用了多少、有没有在借别人的
工具入口     ← 原来那个链接目录,降到最后
```

顺序是刻意的。**原来的版本只有第三块,所以它本质上是个书签栏。**

### 取数一律容错,页面绝不因为后端挂掉而打不开

这是这次改造的硬约束,也是测试里占比最大的部分。理由很直接:**门户是
"哪里都进不去的时候最后还能打开的那个页面"**。它加了两个依赖 Kubernetes
API 的区块,如果这两块能连累整页 500,那这次改造就是净损失——原来那个
链接目录至少永远能打开。

所以每个取数函数取不到时返回 `{"error": ..., "rows": []}`,页面对应区块
显示一句说明,其它部分照常。本机开发环境没有 k8s 也走同一条路径,所以
本地跑这个 app 不需要任何 mock。

### 并发探测

线程池并发,最坏就是一个超时的时间(约 2 秒),而不是 19.5 秒。

**并发引入了一个新的失效模式,已经被测试抓到过一次**:`pool.map` 会把
任何异常原样抛回主线程,一个工具探测出意外就是整页 500。第一版就是这么
写的,写测试时立刻炸了,现在每个探测单独兜异常。

### 作业归属靠标签,不靠猜

`platform_sdk.submit_job()` 现在给 Workflow 打
`platform-sdk/submitted-by: <用户名>`,来源是 JupyterHub 注入的
`JUPYTERHUB_USER`(它就是 Keycloak 的 `preferred_username`,和门户从
oauth2-proxy 拿到的 `X-Forwarded-User` **是同一个值**,两边能对上)。

两条刻意的保守设计:

- **认不出提交人时不编默认值**(不用 `"unknown"`,也不用 `os.getlogin()`)。
  编一个会让门户上出现一堆归属错误的作业,**比不显示更糟**。
- **用户名不符合 K8s 标签规则时(比如邮箱形态带 `@`)宁可不打标签**。
  API server 会直接拒绝非法标签值,那意味着整个作业提交失败——为了一个
  锦上添花的归属标签把主流程搞挂,不能接受。

### 队列用量显示所有组,不是只显示"我的"

要只显示"我的",得先知道当前用户属于哪个组,那需要 oauth2-proxy 透传
groups 头。**改那份配置有真实的登录风险**——它的注释里记着 2026-08-16
两次血泪史(redirect_url 缺端口、issuer 精确比对失败导致 oauth2-proxy
拒绝启动)。这次没有集群可以验证,不动它。

而且显示所有组本身也说得过去:平台内部各组用了多少不该互相保密,能看到
别人在忙,反而解释了自己为什么在排队。

### 模板搬进 `templates/`,但仍然不引前端框架

Jinja 是 Flask 自带的,和引 React 是两回事,[ADR-032](032-self-built-tools-auth.md)
那条"不用前端框架"的约束仍然成立。

样式上补了深色模式(颜色全部走 CSS 变量,深色只重定义变量不重写规则)、
响应式、表格独立横向滚动。

## 还没做的

1. **镜像没重建、集群没验证。** 门户镜像是 digest 固定的,改完源码要等
   CI 重建、更新 `manifests/deployment.yaml` 里的 digest。**在那之前集群上
   跑的还是老版本。**
2. **数据质量概览**没做。要读 OpenMetadata 需要给门户一个 API token,
   那会扩大它的权限面(门户是所有登录用户都能打开的页面),值得单独想
   清楚再做,不是顺手加。
3. **待办审批**没做。审批后端有数据,但需要按人过滤,同样卡在 groups 头。
4. 只显示"我的"队列——见上面,等能在集群上验证 oauth2-proxy 改动时再做。
