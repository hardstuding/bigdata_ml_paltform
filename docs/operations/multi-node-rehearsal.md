## 为什么需要这一步,不是走过场

到 2026-08-22 为止,这个平台**从来没有在多于一个节点的集群上跑过**。
local-lite 是一台 Mac,cloud-full 是一台 ECS。而 `prod` 这一档配置里有
一堆只有多节点才可能生效的东西:

| 配置项 | prod 档 | 单节点上会怎样 |
|---|---|---|
| `postgres_instances` | 3 | CNPG 会把 3 个副本调度到同一台机器,"高可用"名不副实(ADR-038 记过) |
| `kafka_replicas` + `kafka_replication_factor` | 3 / 3 | 三个 broker 挤在一台上,任何一台挂了数据就全丢 |
| `opensearch_replicas` + `opensearch_single_node` | 3 / false | 同上,而且这两个键必须一起切,单节点上切错了 topic/索引根本建不出来 |
| `trino_workers` | 3 | 能跑,但验证不了跨节点 shuffle |
| MinIO 分布式 | **还是 1,故意没做** | 纠删码和磁盘布局绑死,单节点上没法设计 |
| `nodeAffinity` / `taint` 分层 | **还没写** | `environments/prod/README.md` 里"存储层 2 台专用、计算层 4 台"那套布局完全没有落成配置 |

也就是说:**prod 这一档目前只能证明"渲染得出来",证明不了"跑得起来"。**
这正是这个仓库反复强调的那条区别。

## 建议台数:先 3 台,不是 5 台

**理由**:3 台就能把上面那张表里除了最后两行以外的全部验证掉——
Postgres 3 副本跨节点、Kafka 3 broker、OpenSearch 3 节点,都是"最小真
HA"的数字,正好一台一个副本。MinIO 分布式最小需要 4 个盘,可以在 3 台上
每台挂 2 块盘满足(共 6 盘),不需要为它单独加机器。

**什么时候才需要 5 台**:验证 `environments/prod/README.md` 里那套"存储层
2 台专用 + 计算层隔离"的 `nodeAffinity`/`taint` 布局。但那套布局本身现在
**还没写成配置**,先用 3 台把"多副本真的能跨节点起来"证明掉,再决定要不要
为节点分层单独花一次钱。

分两次租(3 台 → 视结果决定要不要 5 台)比一次租 5 台省钱,而且第一次
大概率会暴露一批问题,带着问题去跑第二次更值。

## 演练要验证的东西(验收标准,不是"看着起来了")

按这个仓库的一贯标准,每条都要有独立证据,不接受"Pod Running / ArgoCD
Synced" 当结论:

1. **Postgres 真 HA**:3 个实例分布在 3 台不同节点(`kubectl get pods -o wide` 确认),
   然后**真的把主节点所在的机器关掉**,确认自动故障转移完成、数据没丢、
   依赖它的组件(Keycloak/Airflow/Superset/MLflow/OpenMetadata)能恢复。
2. **Kafka 真 HA**:3 broker 跨节点,建一个 replication-factor=3 的 topic,
   写入若干消息,**杀掉一个 broker**,确认消费端不丢消息、ISR 恢复。
3. **OpenSearch 真集群**:3 节点组成 quorum(不是 3 个互不相干的单节点
   实例——`_cluster/health` 的 `number_of_nodes` 要是 3),OpenMetadata
   的搜索仍然可用。
4. **MinIO 分布式**:这一档需要先设计磁盘布局(见上面),属于演练里唯一
   一块"要先做设计再验证"的,不要指望现场拍。
5. **一键部署在多节点上仍然成立**:`bootstrap-all.sh` 从空集群跑完,
   `TARGET_ENV=prod`。这一条是重点——2026-08-22 的单节点推倒重建暴露了
   两个只有从零拉起才会出现的 bug(ADR-039 末尾),多节点大概率还有新的。
6. **调度分布合理**:没有出现"所有重组件都挤在一台"的情况。

## 成本估算(需要按当时实际价格核对,这里只给量级)

cloud-full 现在这台(16 vCPU / 64 GiB,抢占式)约 ¥4/时。3 台同规格约
¥12/时。演练本身(建集群 + 部署 + 上面 6 项验证 + 故障注入)预计 4-6
小时,量级是 **¥50-80**。

**省钱的关键**:镜像。cloud-full 那台机器上现在有 121 个镜像、约 148GB
(在 `/data/containerd` + `/data/docker`)。多节点新机器如果从零拉镜像,
在境内网络下是几小时起步、而且这几小时机器全程计费。开工前要先想好镜像
怎么过去(`scripts/22/23-*-remote*.sh` 那套远程镜像准备流程,或者给新机器
挂一块从现有数据盘做的快照)——**这件事没想清楚之前不要开机**。
