## 三份文档分别记什么

- **这份 `STATUS.md`**:当前这一次具体部署的实例信息、进度、下一步——
  会过时,下次换一台实例/重新部署时这份文档的内容大部分要重写。
- **`README.md`**:通用的"接入步骤"和"每个组件该给多少资源"参考——
  不随某一次具体部署变化,除非资源建议本身要调整。
- **ADR-054**:这次搭建过程中真实踩到的坑和解法——面向未来(尤其是
  以后迁移自建 IDC 时)复用,记录的是可复用的经验,不是这次的实例细节。

## 过程中做过的关键决策(带原因,方便后来者理解"为什么"不只是"是什么")

- **抢占式实例 → 按量付费**:抢占式实例可能被随时收回,且当时默认设置
  只用 1 小时,跑不完这一整套部署和验证,改成按量付费(可以随时手动
  释放,不会被强制收走)。
- **固定带宽 → 按流量计费**:固定带宽 50Mbps 报价 ¥11.56/时,比实例
  本身(¥3.58/时)还贵,而且真正需要高速传输的是"上传镜像缓存"这个
  单次操作——查证过阿里云入方向流量完全免费,只有出方向按 ¥0.8/GB 收,
  改成按流量计费后合计从 ¥15.60/时 降到 ¥4.04/时,出方向流量按实际
  用量另计。
- **"安全加固"镜像 → 普通镜像**:担心额外的系统加固策略(防火墙/内核
  参数)和 K8s 的 NetworkPolicy/CNI 产生未知的相互影响,换成不带加固的
  普通 Ubuntu 26.04,减少一个不确定因素。
- **6443 端口不对公网开放**:管理这个集群走 SSH 隧道,不是把 K8s API
  server 直接暴露公网——见 ADR-054"安全考量"一节。
